# 引言

如今的模型训练流水线中，主要分为两个部分：算法以及基建。当最终训练出来的模型效果不理想的时候，可能是算法同学导致的，或者是基建本来就出了问题。那么基建同学该怎么才能明正言顺的甩锅给算法同学呢～我们必须要研究出一套能够诊断训练框架的系统，它能够让我们在训练框架经过系统检验后可以有 99%以上的置信度说出：“应该是算法的问题吧。应该是数据的问题吧。这个 reward 感觉不太对啊，再调调吧。”

# 系统详情

那么我们应该怎样设计这个系统呢？其实如果是我们从头自己搭建一个训练框架，那么整个项目的一致性是最高的，其中进行了更新后出现了什么问题我们都可以通过设计预期的测试来进行验证。但是个人的力量毕竟是有限的，很多时候我们都是在和别人的框架项目打交道，但又需要针对自己的使用场景进行适配，这其中如果出现问题，我们很难直接设计相应的测试，毕竟我们不熟悉代码库，让 agent 一口气搞定也不现实。

而且我们面对的模型效果不理想的问题，并非是一个肉眼可见的报错，这种静默的错误，agent 也不方便下手。所以我们的系统需要能够把静默的错误转化成可见的偏差，让 AI 大人也能理解问题（当然我们也会更清楚啦)。
